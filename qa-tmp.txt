1. Test Strategy & Scope

  1.1 Purpose & Objectives

This pack validates the redesigned TechpioAsset Enterprise ITAM platform's authentication, authorization (RBAC/ABAC), and multi-tenant
isolation controls across all three delivery surfaces -- Next.js 15 web, Expo/React Native mobile, and the NestJS v1/v2 REST API. The governing
quality goal is defense-in-depth verification: every access decision is proven at the gateway/guard layer, the policy (ABAC) layer, and the
PostgreSQL RLS backstop, not merely in the UI. Security controls are treated as functional acceptance criteria, not optional hardening.

1.4 Test Data & Tenants

 Minimum three tenants: T-Alpha , T-Beta (peer customers, must be mutually invisible), T-MSP (Super Admin fleet plane).
 Full role coverage per tenant: one seeded principal for each of the 13 canonical roles, plus one custom role and one readonly:true role for
 invariant tests.
 Org tree seeded so DEPARTMENT , DIRECT_REPORTS , and OWN scopes have non-trivial membership (a Dept Mgr with 2 reports and cross-
 department decoys).
 Cross-tenant collision data: identical asset tags / serials in T-Alpha and T-Beta to prove per-tenant unique keys and RLS row filtering.
 Secrets/PII fixtures are synthetic only; no real credentials. MFA seeds use fixed TOTP secrets for deterministic OTP generation.

  1.5 Entry & Exit Criteria

Entry: build deployed to target env; RLS policies applied and migration-check green; test IdP reachable; seed fixtures loaded; all 13 role principals
authenticate. Exit: 100% of P1 scenarios pass on all applicable surfaces; zero open S1/S2 defects; the Auditor read-only invariant, cross-tenant
isolation, and no-privilege-escalation suites pass with zero exceptions (these are release-blocking regardless of severity math); traceability matrix
shows every in-scope spec control mapped to 1 executed case.

1.6 Defect Severity & Priority

Severity       Definition
S1 Critical    Cross-tenant read/write, privilege escalation, auth bypass, Auditor mutation succeeds, refresh-reuse not revoked
S2 High        Scope leak within tenant (e.g., Employee sees others' assets), MFA/step-up bypassable, force-logout ineffective
S3 Medium      Correct backend denial but misleading UI (control shown-then-403), inconsistent error envelope
S4 Low         Cosmetic, copy, non-blocking UX on a secured path

Priority: P1 = release-blocking security/happy-path (run every regression); P2 = high-value negative/edge; P3 = boundary/cosmetic. Any cross-
tenant or escalation finding is S1 and P1 by definition.

1.7 Dual-Surface Execution Rule (mandatory)

Every functional scenario is executed on BOTH the Web UI and the Mobile UI, and against the API directly where an endpoint exists. A pass on one
surface never substitutes for another. Scenarios are tagged Surface=Both ; where the mechanism genuinely differs (biometric unlock, offline-queued
